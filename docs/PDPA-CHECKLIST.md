# รายการตรวจ PDPA ก่อนเปิดซิงก์ Google Sheets

ข้อมูลสุขภาพเป็นข้อมูลอ่อนไหวตาม PDPA การที่แอปไม่ส่งชื่อและส่ง HN เฉพาะค่า hash ช่วยลดความเสี่ยง แต่ **ไม่ทำให้ข้อมูลหมดสภาพเป็นข้อมูลส่วนบุคคล** (ผู้ที่มี salt และรายชื่อ HN ย้อนหาตัวบุคคลได้) จึงต้องได้รับอนุมัติจากผู้รับผิดชอบก่อน

- [ ] ผู้รับผิดชอบด้านคุ้มครองข้อมูลส่วนบุคคลของ รพ. (DPO หรือผู้ที่ รพ. มอบหมาย) รับทราบและอนุมัติเป็นลายลักษณ์อักษร
- [ ] ฝ่ายสารสนเทศ/ไอทีของ รพ. อนุญาตให้ใช้ Google Workspace ของกลุ่มงานเก็บข้อมูลนี้
- [ ] ใช้บัญชี Google ของกลุ่มงาน (ไม่ใช้บัญชีส่วนตัว) เปิดยืนยันตัวตนสองชั้น และแชร์ Sheets เฉพาะเภสัชกรที่เกี่ยวข้อง
- [ ] กำหนดผู้ถือ salt และ token (เก็บแยกจากไฟล์ Sheets, ไม่ส่งทางแชตส่วนตัว, ห้ามเปลี่ยน salt ภายหลังเพราะ hash เดิมจะใช้ไม่ได้)
- [ ] ผู้ใช้ทุกคนรู้ว่า **ห้ามพิมพ์ชื่อ/เลขบัตร/ที่อยู่ผู้ป่วยในช่องข้อความอิสระ** (ประวัติแพ้ยา, หมายเหตุ, ข้อความ RCA) เพราะช่องเหล่านี้ส่งขึ้น Sheets ตามที่พิมพ์
- [ ] กำหนดอายุการเก็บข้อมูลและผู้ลบข้อมูลตามกำหนด (ปุ่ม 🔒 → อายุข้อมูล) และกำหนดวิธีลบบน Sheets ด้วย
- [ ] มีแนวทางเมื่อข้อมูลรั่วหรือเครื่องหาย (แจ้งใคร ภายในกี่ชั่วโมง เปลี่ยน token อย่างไร)
- [ ] ทดสอบด้วยข้อมูลสมมติก่อน แล้วเปิด Sheets ตรวจว่าไม่มีชื่อผู้ป่วยและ HN เป็นค่า sha256
- [ ] วางแผนย้ายไปฐานข้อมูลในเครือข่าย รพ. (ระยะที่ 2) กำหนดเวลาชัดเจน

เมื่อครบทุกข้อ จึงติ๊ก "ได้รับอนุมัติ" ในหน้าตั้งค่าซิงก์ของแอป
